# 记账单（1.3.0）

## 目的、API 与数据

保留微信Excel、支付宝CSV、招商银行PDF解析，分类规则、支付宝付款方式过滤、账单模板和Excel导出。管理API `/status`、`/reload`、`/category-rules`、`/alipay-filter-rules`；原始上传使用 `/api/pocket-kit/bill-manager/upload?role=wechat|alipay|cmb&name=`，二进制最多20MB；下载为 GET `/api/pocket-kit/bill-manager/download`。

`.local/data/bill-manager/` 保存source原始账单、config规则和accounts账户映射。9个原文件共219922字节逐文件hash一致；原源码硬编码的个人账户名称提取到私有accounts.json，分发代码只保留通用默认值。导出不上传第三方，不修改原账单。客户端表格取消分页，连续渲染当前来源的全部匹配记录；纵横滚动均限制在表格容器，表头与日期列固定。搜索仅筛选当前来源的预览，不影响“导出全部 Excel”；导出仍包含各来源按业务分类/过滤规则处理后的全部记录，界面明确提示此区别。

## 交互设计（2026-11-08）

- 按用户要求采用紧凑布局：移除页面大标题、描述、双排Tab及常驻使用说明。首行为“首页 / 会话 / 来源下拉（含条数）/ 导出全部 / 更多”，首页与会话均直接外露，第二行为搜索和匹配条数，下面全部留给表格。导入、分类、支付宝过滤、重新读取及导出范围说明收入“更多”；支持外部点击/Escape关闭菜单。
- 导入和规则直接打开模态弹层，不再经过单独Tab页。导入每个来源一行，分类编辑的一、二级分类并列。按钮最小34px高、菜单项36px、表格紧凑30px行高，输入保留16px防止手机聚焦缩放；这是用户明确要求的44px触控规范例外，只作用于记账单。
- 导入按钮统一中文“选择文件”；原生文件输入透明覆盖按钮，仍保留键盘与触屏文件选择能力。导入成功切换到对应来源并清空搜索。表格没有分页/加载更多，横向不截断数据；超大账单全量DOM的性能尚未压测。
- 规则编辑在模态弹层中进行，支持 Escape/关闭/遮罩和恢复焦点；取消确认、保存失败保留草稿，必填项由表单与后端共同校验。
- 保持原后端接口与导出行为，未写入或替换真实账单文件。

## Excel 预览兼容（2026-11-08）

- 导出端通过当前 `xlsx` 库的 `sheetFormat` 写入工作表级 `sheetFormatPr defaultRowHeight="15"`（15磅/20px），大纲层级为0；不改变单元格值、分类规则、列顺序或工作表名称。未修改DSH内置预览插件。
- 原因：未显式指定默认行高的文件在当前DSH预览解析器中产生NaN行高，继而导致行位置无效；仅设置逐行行高不作为默认行高修复的替代。
- 验证：新增虚构数据回归检查实际XML默认行高与全部映射单元格；账单/工具模块相关8项测试及 `npm run check` 通过。对已交付账单生成单独兼容副本，99×8单元格逐格一致；未经修改的当前预览解析器读取行高20px，99行、8列正常。未进行浏览器UI验证或记账软件实际导入验证；未重载运行中的Host，源码修改不等于运行实例已更新。

## 支付宝日期格式（2026-11-08）

- 支付宝导出为 `月/日/年`（如 `11/7/26`），导出时统一转为 `YYYY-MM-DD`（如 `2026-11-07`）；已是 ISO 的输入同样归一为年月日，时间部分不进入日期列。微信仍保留完整日期时间，招行保留原值。
- 两位年份按 20xx 解释；若第二段大于 12 且第一段不超过 12，按 `日/月` 顺序纠正一次；无法识别的值原样保留，不猜测。
- 验证：新增虚构数据回归覆盖 `11/7/26`、`9/25/26`、`2026-10-02`、`12/31/26` 与招行过滤；9 项测试与 `npm run check` 通过。真实支付宝账单重导出 29 条，日期范围 2026-09-25 至 2026-11-07，金额与分类不变。未做记账软件实际导入验证，未重载运行中的 Host。

## 招商备注补充支付宝商品（2026-11-08）

- 招行“备注”仍为 `交易摘要 + 对手信息`；若支付宝里存在同一笔的付款记录（付款方式命中 `alipayFilterRules` 关键词，默认“招商银行”），且**日期+金额唯一命中**，追加 `支付宝：商品说明`。日期按 `YYYY-MM-DD` 与 `月/日/年` 归一后比较，金额按分比较。
- 同日同额出现多笔、或只有支付宝余额付款时**不补充**，避免张冠李戴；支付宝导出仍排除这些招行付款记录，不重复记账。
- 验证：新增虚构回归覆盖唯一命中、同日同额两笔、非该卡付款、无对应记录四种情况；10 项测试与 `npm run check` 通过。真实数据招行 24 条中 7 条补入商品（滴滴 4、闲鱼寄件 2、闲鱼风扇 1），支付宝仍为 29 条。未做浏览器与真实导入验证，未重载运行中的 Host。

## 生命周期与取舍

请求串行避免同模块配置/上传相互覆盖；上传临时文件验证来源后才替换“当前”账单。原迁移文件保留。PDF与电子表格解析为本机同步/异步库，20MB限制不等于恶意压缩包完整隔离；只应导入可信官方账单。已保留旧模板逻辑，不新增自动财务判断。未使用真实账单运行写入测试；外部来源格式仍需用户导出后核对。

## 共同接入与移动端

客户端由 `features/utilities/client.js` 装配 React 页面，不嵌入旧 HTML、不另起服务器。工具箱卡片打开 `pocket-kit.bill-manager`；Host 条目为 `pocket-kit-bill-manager`。管理请求走已认证的 `POST /api/pocket-kit/bill-manager`，JSON envelope 为 `{path,method,body}`，要求 `X-Pocket-Kit: 1` 和同源 JSON。路径限制在功能内部。Agent 工具 `pocket_bill_manager` 先 help 发现接口，与 UI 共用 FeatureService；权限授予、凭据和真实终端命令只在 UI。

采用主题色、卡片分组、44px 控件、16px 输入、可换行长文、安全区底部留白和局部滚动表格；加载、空列表、错误和手动重试均有入口。移动宽度 320/375/390/430px、软键盘、深浅主题还没有真实浏览器验收，不以 CSS 或注册测试替代。
