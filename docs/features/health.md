# 健康记录（1.3.0）

## 目的、API 与数据

健康默认对比表格（日期列固定、点日期或指标打开完整记录、全部记录连续展示且无分页），可切换卡片；人员切换、记录新增/编辑/删除、关注指标/显示列配置和 Excel 导出。管理、视图配置与记录编辑放在原生模态弹层中；常用字段优先编辑，支持展开全部字段并保留已有隐藏值。不提供医疗诊断。功能内 API 保留旧 `/people`、`/people/:id`、`/people/:id/config`、`/people/:id/records[/recordId]` 和 `/people/:id/export?scope=all|visible`。写入使用完整 cells，修改/删除使用 revision；过期修改返回409，不覆盖他人更新。

数据为 `.local/data/health/health.sqlite`，包含人员、记录、导入指纹和原有字段迁移备份。SQLite online backup 生成一致性快照，而非直接复制活动数据库；校验了1位人员、25条记录、1个导入指纹及 integrity_check=ok。原始记录与显示偏好均保留。客户端只在打开页面时读取，未写浏览器存储。Excel 导出由本机生成。删除不可恢复，UI 要求确认；原项目数据库可作迁移回滚源。

## 紧凑交互（2026-11-08）

- 与记账单共用紧凑页面壳，不显示大标题/副标题。首行“首页 / 会话 / 人员下拉 / 新增 / 更多”，两种返回入口均外露；第二行搜索与条数，其余空间用于表格。
- “更多”收纳显示字段、卡片/表格切换、人员/字段管理、导出、刷新及非诊断说明，支持外部点击和Escape关闭。表格无分页，固定日期和表头；指标过长时单行省略，点击指标或日期打开完整编辑表单，不仅依赖hover查看。
- 字段编辑两列、日期独占一行，文本框可滚动/手动拉高；失焦不改变高度，避免按钮在点击时移动。保留完整cells及失败草稿，不变更Agent/数据库接口。
- 按用户要求，按钮34px、表格单元格按钮28px、输入16px；此处是默认44px触控规范的明确例外。超大记录量DOM性能与真机软键盘仍未验收。

## 生命周期与取舍

Host 卸载关闭数据库；页面卸载取消 fetch。SQLite 事务和 revision 防冲突，原有颈动脉字段迁移标记保留。记录编辑先展示日期、来源、显示字段与已有值字段，其余可展开；保存失败保留草稿，成功写入即关闭编辑，避免刷新失败后重复新增。模态弹层支持关闭、Escape、遮罩与焦点恢复；真机软键盘仍待验收。

## 共同接入与移动端

客户端由 `features/utilities/client.js` 装配 React 页面，不嵌入旧 HTML、不另起服务器。工具箱卡片打开 `pocket-kit.health`；Host 条目为 `pocket-kit-health`。管理请求走已认证的 `POST /api/pocket-kit/health`，JSON envelope 为 `{path,method,body}`，要求 `X-Pocket-Kit: 1` 和同源 JSON。路径限制在功能内部。Agent 工具 `pocket_health` 先 help 发现接口，与 UI 共用 FeatureService；权限授予、凭据和真实终端命令只在 UI。

采用主题色、卡片分组、44px 控件、16px 输入、可换行长文、安全区底部留白和局部滚动表格；加载、空列表、错误和手动重试均有入口。移动宽度 320/375/390/430px、软键盘、深浅主题还没有真实浏览器验收，不以 CSS 或注册测试替代。

## 自定义字段与 Agent（2026-11-08）

- `GET /people/:id/columns` 返回该人员全部字段及配置 `revision`，不读取健康记录。`GET /people` 的 columns 仍仅为内置字段；人员详情返回内置及自定义字段。
- `POST /people/:id/columns {label,revision}` 添加字段，返回 `{column:{id,label},person}`；自动加入当前人员显示列，并推进配置 revision。字段名称1–80字符、不可与现有名称重复；每人最多100个自定义字段。重复或旧版本返回409，事务回滚不遗留字段。
- 自定义定义保存在同一 SQLite 的 `custom_columns` 表，ID 为 `custom_<整数>`；按人员隔离，历史 cells 不迁改。页面、记录校验、视图配置、Excel 使用相同定义。目前不支持字段重命名或删除。
- Agent 先确定人员，再读 columns；需要新指标时添加字段，随后用返回 ID 调用 `POST /people/:id/records {cells:{c0:日期,...}}`。日期必填，其余可省略。PUT 仍为完整替换：先读取单条、合并 cells 并携带当前记录 revision，不能把局部字段当完整记录提交。
- 新字段、记录等真实写入须有用户明确请求。开发写入回归全部使用隔离 SQLite / 虚构浏览器接口，未增删真实健康记录。

补充：GET `/status` 仅返回就绪状态和人数/记录数；`/people/:id/records?offset=0&limit=10` 支持1–50条分页，`/people/:id/records/:recordId`读取单条，供Agent缩小私人数据上下文。
