# 音乐与小爱迁移记录（1.1.0）

## 范围与入口

来源为用户指定的 allinone 项目。来源数据始终保持只读，未改原数据或原配置；2026-11-07 经用户确认已停止其整个服务以释放小爱端口。

- **音乐 tab**：搜索、网易云会员/声音、扫码或 Cookie 登录、下载队列、试听/本机下载、移动/改名/删除、音乐信息/歌词/封面编辑。
- **小爱音箱 tab**：整合“小爱播放”和“音响控制”两个子视图；保留曲库、播放列表、收藏、循环/随机/队列、监听/音量/播报、自动歌单与规则、快捷控制和历史。
- 侧栏分别有音乐和小爱音箱入口。2026-11-07 起两个入口彻底独立：音乐页只保留下载与下载库管理，不再显示小爱音箱 tab；小爱页也不再显示音乐 tab。沿用宿主主题与页面框架，无 iframe 或替代 GUI。

2026-11-07 的入口解耦仅改客户端装配层，保留面板 key、Host 条目、API 与全部数据；验证记录见[音乐](features/music.md)。

业务设计和完整 API 分别见[音乐](features/music.md)、[小爱音箱](features/xiaoai.md)，实际 DSH 路由和共享工具见[架构](architecture.md)。

## 数据处理

一次性脚本 `scripts/migrate-allinone.mjs` 拒绝覆盖已有目标；已执行本次迁移，不要再对同一目标运行。源数据复制后逐文件比对，目录 0700、普通文件 0600；既有可执行文件保留为 0700，未执行。

| 来源模块数据目录 | 复制至 `.local/data/` 下同名目录 | 数量 |
| --- | --- | --- |
| music-download | 下载文件、catalog、移动目标、网易登录密文、已有下载器 | 6 文件，9,759,658 字节 |
| xiaoai-music | 音箱配置、曲库索引、播放列表/收藏/播报、自动播放配置和状态、已有 Python 数据依赖 | 97 文件，3,519,934 字节 |
| xiaoai-assistant | 快捷控制与按设备保存的指令历史 | 1 文件，1,735 字节 |

只迁移模块需要的环境变量到 `.local/integrations.json`，没有把整份环境配置复制进源码。为兼容已有网易密文，将旧加密密钥保存在本地 `NETEASE_COOKIE_SECRET` 字段；未把原项目登录 token 作为新 DSH 登录凭据。没有输出 Cookie、密钥或用户数据内容。

旧部署的 `MUSIC_DOWNLOAD_DIR` 是不同环境的绝对路径：首次读回检查发现列表为空，而复制目录有两首文件。现已明确将下载目录和已有 media-get 路径重定位到新 `.local/data/music-download/`，再次读取确认 **2 个下载文件可见，网易登录密文可解密**；没有改写音频内容。密文解密不等于已验证第三方登录仍有效。

小爱只读加载确认：**2 个设备配置、16 个收藏、1 个自动歌单、1 条自动规则、1 个快捷控制**；已有播放列表和各类历史保持原结构。4 个配置曲库目录在当前主机均可访问。外部 NAS 曲库保持引用，不复制整座曲库；用户以后在配置页面改路径前应确认新目录边界。

**`.local/`、私人配置、媒体、二进制和回滚数据均不得提交或打包。** 原项目可继续独立运行，但迁移后双方数据不再自动同步。

## 小爱为什么默认暂停（迁移时策略）

2026-11-09 用户确认 Allinone 不再常驻，要求小爱自动连接：现有局域网许可已确认且未设置 `XIAOAI_AUTO_START=false` 时，Host 初始化自动启动全部配置的自有 worker；保留端口冲突与私网限制。以下为迁移历史，当前策略见[小爱音箱](features/xiaoai.md)。

旧实现初始化会自动启动每台音箱的 Python worker，并启动网络监听与自动播放。照搬会造成端口冲突、重复调度甚至误控制原服务。因此新版初始化只读数据，**没有启动任何 worker、播放、播报或定时任务**。

启用步骤（2026-11-07 已执行）：

1. 由用户确认停用旧 allinone；本次用户选择停止整个 Allinone 服务（`pm2 stop allinone` 并 `pm2 save`），未改其源码和数据。新版只回收自己创建的子进程，遇到端口占用返回冲突。
2. 确认音箱协议只能从可信局域网访问，并阻止公网暴露。旧设备协议的 WebSocket 和音频服务没有登录认证，不能把它们误认为受 DSH 登录保护。
3. 用户明确确认风险后，在 `.local/integrations.json` 的 `env` 中设置 `XIAOAI_ALLOW_LAN_UNAUTHENTICATED` 为字符串 `"true"`，以及音箱可访问的私网 IPv4 `XIAOAI_BIND_HOST`。默认不授予该风险许可；禁止 `0.0.0.0` 和公网地址。回环地址仅适用于本机测试，实体音箱通常无法访问它。
4. 通过 Plugin Manager 重新加载 `pocket-kit-xiaoai` Host；本次随后通过同一 Host 的 Agent 工具显式启动两台 worker（与页面“启动服务”走同一后端），页面启动同样需要用户明确点击。启动后可能恢复已启用的自动播放规则，先检查规则和时间。

实际启用结果：两台 worker 均已启动，设备连接成功，首次曲库索引各 2738 首，搜索和音量写入通过；真实播放、语音指令、自动规则触发和手机布局仍未验收。详见[小爱音箱](features/xiaoai.md)末尾的启用记录。

管理操作始终走 DSH 鉴权；worker 控制 API 仅监听回环并使用每次启动随机 Bearer token。旧 shell 参数引号注入、目录逃逸及 WebSocket 分片大小问题已修正。LAN 设备协议的兼容限制没有被伪装成完整安全隔离。

## 测试与验证边界

- Node、Python 3、FFmpeg、ffprobe 已在当前环境可用。
- 最终 `npm run verify` 完整构建、语法/元信息检查和 **86 项测试通过**，包括请求取消和设备切换竞态修复。`git diff --check` 通过。
- 实际 npm 打包清单 **67 文件**，包含 Python runtime、索引组件和停止词表，不含私人数据、凭据、缓存或测试；还将已迁移密钥值与可提交源码逐一比对，未发现泄露。
- Node 测试包括 HTTP/Range 桥、同源请求保护、来源限制、目录逃逸、Cookie 安全保存、实际临时文件操作、请求取消、Host 清理和默认不启动音箱。
- 小爱测试包含 5 项 Python 纯模拟安全检查；模拟不等于真实音箱验证。
- 私有数据只做本地读取和密文解密验证，没有搜索/下载真实平台内容，没有执行 media-get、FFmpeg 标签写入或操作真实音箱。
- 手机界面采用 44px 触控、16px 输入、窄屏单列/换行、安全区与异步错误提示；没有浏览器控制，320/375/390/430px 布局、软键盘和设备实际播放仍未验收。
- Agent 工具通过 help 延迟发现操作，不把全部 API 参数堆进首次提示。业务方法与 UI 共用；工具/界面一致性以隔离测试验证，未用正式数据执行写入测试。

## 安装与运行时核验

通过 Plugin Manager 卸载旧工具箱链接后，重新安装当前根包 `@local/pocket-kit@1.1.0`，返回 `application: applied`，无 warnings；没有手写 profile 文件或重启 DSH 服务。音乐与小爱 Host 条目均在运行时目录中。新注册工具的 help 可正常读取，真实只读查询音乐 `/status` 返回 200、下载器就绪、加密登录已载入；小爱 `/profiles` 返回 200，两个设备都为 stopped，未启动任何 worker。

已连接客户端 Slot 树显示 `pocket-kit.music` 和 `pocket-kit.xiaoai` 侧栏入口 active，清单原入口仍在。注册成功不代表已完成点击/布局验收；升级后应刷新原 DSH 页面加载最新构建，无法据此保证手机视觉、图标渲染或第三方服务可用性。

## 已知约束

media-get 的内部联网不受 Node 侧 DNS 固定策略管控；已有限制受支持平台来源，但它不是网络沙箱。上游工具包没有签名核验，外部工具下载也没有严格的过程中磁盘配额；不要将本个人工具开放给不可信用户。每项下载尚无单独取消按钮，Host 卸载会取消本实例任务。仅下载有权访问的内容。

音乐和小爱视图当前以中文交互为主，包与各 Host 提供中英文显示元信息。不会承诺自动热更新：升级后按安装结果处理 Host 重载，并刷新原 DSH 页面。

## 回退

旧 allinone 源项目和数据保留原样。需要回退时先停用新音箱 worker和对应新 Host，避免两套协议桥/自动化并行；再执行 `pm2 start allinone` 恢复旧服务。迁移后新增的下载、收藏或指令历史不会自动写回原项目，回退前先备份并明确选择数据版本。不要删除新旧数据来解决启动冲突。
