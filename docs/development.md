# 开发与新增功能

## 开始前

1. 阅读[架构](architecture.md)、目标功能文档；涉及数据先读[隐私规范](security-privacy.md)，涉及 UI 读[移动规范](mobile.md)。
2. 以当前源码为准。不要读取私人书签来理解功能，不在正式清单上跑写入测试。
3. 修改 DSH 接口前通过 Cordis Inspect 查询确切服务、事件、配置和 Slot 契约，不根据旧示例猜接口。

## 新增功能流程

1. 复制[功能模板](features/_template.md)，说明目的、入口、非目标与数据风险。
2. 在 `features/<feature>/` 内组织业务实现和测试。业务模型不依赖 UI，Host 负责鉴权接入与资源管理，Client 负责交互与展示。
3. 将客户端功能接入统一构建；有服务端能力时增加 Host 子路径导出与 bundle 条目。检查依赖、配置 schema、显示元信息和资源是否随包分发。
4. 选择真正需要的 UI 入口；复用已声明的菜单槽或 DSH Slot，不读取其他功能 DOM 来定位。
5. 定义数据路径、格式版本、并发语义、迁移和备份；定义 API 的输入、响应、错误码、认证及副作用。
6. 所有定时器、订阅、监听、请求、流和任务有明确的取消及卸载方案。避免每次打开页面重复注册全局资源。
7. 添加正常、异常、并发、取消和卸载测试；按移动规范验证真实交互。
8. **在对应功能文档记录 API、数据、重要决策及原因、生命周期、验证结果和限制。** 更新 AGENTS 中的索引即可，不向索引堆实现细节。

## 构建与验证

根包脚本：`npm run build` 构建 `dist/client.js`，`npm run check` 运行静态检查，`npm test` 运行功能和根测试，`npm run verify` 按构建、检查、测试顺序执行。单功能测试可用 `node --test features/<feature>/*.test.js`。测速引擎由根构建内联，无需运行旧子构建。已执行结果及验证范围见[迁移记录](migration.md)；后续变更需要重新运行相关检查。

完成一次变更至少记录：

- 实际执行的命令、环境、结果；未执行的项目直说未执行。
- 单元 / API 集成 / 客户端注册测试分别覆盖什么。
- 打包清单确实不含 `.local/`、私人数据、凭据和临时截图。
- 安装后的 Host 条目及 Client 注册情况；注册成功不等于 UI 验收通过。
- 浏览器和宽度、键盘及错误状态的实际验证范围。模拟 DOM 不证明视觉布局正确。

不要承诺自动热更新，除非已确认当前 DSH checkout 的 `pnpm run dev:web` watcher 正在运行。构建客户端后仍应遵从安装返回的应用 / 重启提示，并在既有 GUI 验证；另起服务器不等于更新当前 DSH。

## 安装迁移与回滚

每次迁移先确认根包 exports、Host 子路径、客户端载体和 patch 条目，再通过 DSH 插件管理能力执行；不手工重写 profile 配置。先停用冲突的旧条目，避免新旧 Host 同时注册相同 API，保留可恢复代码与数据的回滚路径。

私人数据迁移不得打印内容或盲目覆盖已有目标。书签使用 `.local/bookmarks.json`；清单保留默认路径，曾配置自定义 `dataFile` 时必须先确认新条目的路径设置再写入。安装后依据返回结果处理重启并刷新原 GUI，分别验证后端激活与客户端加载。

1.0.0 合包已归档旧目录至 `.local/legacy-plugins/`，该目录包含私人数据，禁止提交和打包。[迁移记录](migration.md)保存实际安装、数据处理、40 项测试、打包检查、浏览器限制与未执行的回滚步骤。后续操作追加真实记录；未经授权不修改正式数据或 profile。
